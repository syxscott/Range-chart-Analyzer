# Pinned upper bounds for the OPTIONAL dependency set.
#
# WHY: requirements.txt holds lower bounds ("Pillow>=12.3.0"), so a fresh
# `pip install -r requirements.txt` in three months resolves to a DIFFERENT
# set than today. For a tool whose results get published, "I reran it and
# got the same answer" needs the environment to be pinned too -- README's
# reproducibility promise currently covers only the data side (image
# SHA-256 + provenance sheet), not the environment side.
#
# pip's -c is a first-class feature; no new toolchain, no lockfile format,
# no per-platform lock files (those break on pywin32 vs pyobjc).
#
#   pip install -r requirements.txt -c constraints.txt
#
# Dependabot bumps requirements.txt's lower bounds. When it does, it MUST
# bump the matching line here too -- and that extra diff line is a feature:
# it makes the actual version change visible in review. A lower-bound-only
# PR shows no concrete version at all.
#
# HONEST LIMITATION: this does NOT pin transitive dependencies (PySide6
# pulls shiboken6, PySide6-Essentials, ...). The risk is low here because
# the core path is stdlib and the Qt ABI is held by the PySide6 /
# PySide6-Fluent-Widgets VERSION PAIR below. A full lock file would cost
# more maintenance than it buys for a single-maintainer research tool.
#
# Verified against PyPI requires_python on 2026-11-05; all satisfy the
# python_version >= "3.10" markers in requirements.txt.
