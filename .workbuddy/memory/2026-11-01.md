### 四、本轮抓到的四个真问题（都值得记住）

**1. `pytest 目录 + 目录内文件` 会静默丢掉整个目录（最重要）**

```
pytest a/ a/other.py      -> 只收集 other.py   ❌ 静默，exit 0
pytest a/ ../other.py     -> 两者并集          ✅
```

旧 CI 命令 `pytest tests/ tests_core.py` 一直是好的，**只因为 tests_core.py 当时在仓库根、不在 tests/ 里**。文件一移进 tests/，同样的命令只跑 46 项（而非 4360），且 exit 0。已改为只传目录，tests_core 走独立的脚本模式步骤（其退出码即门槛）——并在 ci.yml 里写了注释防止后人"帮忙"把它加回去。

**2. 迁移脚本重复执行会自我破坏**

脚本把 `os.path.dirname(os.path.abspath(__file__))` 替换成锚点名。**跑第二次时，替换会命中它上一次刚写出的锚点里最内层那次调用**：

```
第一遍：REPO = dirname(dirname(dirname(abspath(__file__))))
第二遍：REPO = dirname(dirname(REPO))        ← 解析成 tests/，不是根
```

连带把注释写重复，并让 5 个原本叫 ROOT/root 的文件出现「定义改名 REPO、使用仍是 ROOT」的裂口。**修复必须以 HEAD^ 里的原始变量名为准**，不能统一改成 REPO。

**3. 本地全绿 ≠ CI 能过（本项目第三次同类）**

锚点错了以后本地 17 个套件照样跑绿——因为本机 cwd/import 方式恰好能解析到 `rca_core`（从无关目录 `import rca_core` 实测会报 ModuleNotFoundError，所以不是全局安装，而是运行方式的巧合）。CI 在干净解释器上立刻炸。
**改用结构性验证**：用 AST 求值每个锚点、断言结果等于仓库根。17/17 通过。这比"跑一遍看着是绿的"可靠。

**4. `tests_gui_fluent.py` 是唯一没有锚点的 harness**

它不碰任何文件，所以迁移脚本没动它。它以前能 import `gui_fluent` **纯属巧合**——脚本就在仓库根，Python 把脚本所在目录塞进 sys.path[0]，而那就是根。移深一层，两个 import 全断。已显式补上锚点。

另外 `tests_server.py` 里断言「.py 后缀被拒」用的路径 `/tests_server.py` 在移动后**文件已不存在**，404 会从"后缀被拒"退化成"文件不存在"，测试变弱——已改指自身新位置。

### 合并前查的关键事实（决定了这批能不能直接合）

- **`requirements.txt` 的 `python_version` 标记是过时的**：写着 `>= "3.8"` / `>= "3.9"`，而 README 与 CI 早已是 **Python ≥ 3.10**。
- **新版本让这个过时标记变成真故障**：查 PyPI `requires_python` 实测——**Pillow 12.3 要 ≥3.10、PySide6/Addons 6.12 要 ≥3.10、keyring 25.7 要 ≥3.9**。标记若留在 3.8，在 3.8 解释器上 `pip install -r requirements.txt` 会报"no matching distribution"而不是跳过可选包。
- 因此**先合并、再单独一个 commit 把 10 个标记统一到 `>= "3.10"`**（`a225693`），并补 CHANGELOG。
- **验证方式不是"看着对"**：写了交叉校验脚本，逐条比对「标记下限 ≥ 该固定版本自身的 requires_python」，10 项全过、0 mismatch。
- **qt job 装的是未锁定的 `PySide6`/`Pillow`**（`pip install PySide6 ...`），所以它跑绿本身就等于在最新版上验过——这是判断 6.12 / Pillow 12 可以合的依据，不是猜的。
