# 2026-11-07 下半场：v0.4.0（A 组 11 项收口）

## 🔴 最重要的发现：所谓"本机 socket 环境性偶发"其实是 **NO_PROXY 缺失**

- 本机有 `HTTP_PROXY=HTTPS_PROXY=http://127.0.0.1:8547`，但 **`NO_PROXY` 未设置**。
- 后果：`urllib` / `http.client` 访问 `127.0.0.1:<port>` 的请求被送去代理，表现为
  **60s timeout** 或 `WinError 10053`。`tests/test_server_mode_whitelist.py` 单个文件
  从 **60.68s 超时** 变成 **4 passed in 1.89s**，只因为加了 `NO_PROXY=127.0.0.1,localhost`。
- **这推翻了 2026-09 以来的"勿再排查、环境性偶发"结论**：那条结论把
  `test_non_ascii_csrf_token_rejected_cleanly` 的 10053 归为不可诊断。真实原因是代理。
- 以后跑任何 loopback HTTP 测试（`tests/test_sprint_b_server.py`、`test_server_mode_whitelist.py`、
  `test_server_*.py`、`test_gui_fluent_ssrf.py` 等）都必须：
  ```bash
  NO_PROXY="127.0.0.1,localhost" no_proxy="127.0.0.1,localhost" pytest ...
  ```
- 判断方法：先 `env | grep -i proxy`；若 `*_PROXY` 指向 127.0.0.1 而 `NO_PROXY` 为空，就是这个坑。
- 隔离对照的正确做法（本次用过）：`git worktree add --detach <tmp> HEAD` 后在干净 HEAD 上复跑，
  证明失败与本次改动无关。注意 `git worktree remove` 前先 `git worktree prune`，
  否则临时目录被 safe-delete 拦掉后会留下"missing but already registered"。
