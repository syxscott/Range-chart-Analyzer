## 关键教训（新增）

1. **全量测试抓到我引入的真 bug**：P0-1 修复时给 `js/aggregate.js` 加了 `rcaPyFloatTransliterate`，与 `js/minimax.js` 全局同名 → `test_nonfinite_spelling.py` 失败。无模块系统下 `<script>` 顺序会静默决定哪个 body 生效。改名 `rcaAggPyFloatTransliterate`。**新加全局函数必须先查重名**。
2. **验证工具本身又错了 2 次**：① `release_check` 里 `s.count('version: 0.1.4') == 1` 断言失败（实际 2，顶层+缩进都含子串），导致 `__init__.py` 改了 CITATION 没改，短暂不一致；② 变异脚本 `assert count == 2` 实际 1（两处缩进不同），文件根本没改却以为验证通过。都是"先证明工具对"的老规律。
3. **并发改文件会影响后台全量 pytest**：第二次跑时在测试运行中改了 CHANGELOG/CITATION/版本号。结果 4385 项只有 1 个已知偶发失败，说明没破坏测试，但流程上应避免。
4. **git 推送失败根因**：本机 `http.proxy=http://127.0.0.1:7890` 对 git TLS 握手有问题（schannel / unexpected eof），而 `gh` 能连。解决：`git -c http.proxy= -c https.proxy= push origin main`。以后遇到 TLS handshake 先试绕过代理。

## 发版后 CI 暴露的 3 个问题（均已修，最终 CI 待确认）

1. **发版门设计错误**：`release_check.py --release-ready` 原要求 `tag == HEAD`，发布后任何新提交都会让门永久变红。改为 `git merge-base --is-ancestor tag HEAD` + 读 tag 自身字节确认 PBDB 修复 + 报告落后的提交数。`repo_health` 的 release 检查本来就容忍落后（只看 tag 字节）。
2. **build.yml 首次在 CI 失败**：`test_payload_policy.py::test_lxml_stays_because_openpyxl_uses_it` 报 `lxml.etree` 的 importers 为空。根因不是测试错，是 **CI 干净环境没装 lxml**（openpyxl 的可选加速依赖），导致 CI 构建产物与本机发布产物不同——正是可复现性问题的实例。修法：把 `lxml>=5.3.0` 补进 requirements.txt / constraints.txt(==5.3.0) / deps job import 列表 / README。**不要削弱这条测试**，它抓到了真差异。修后手动触发 build workflow → 全绿（构建两 exe + `/health` 冒烟 + payload 策略 8 步全 success）。
3. **F821 本地验证盲区**：`scripts/release_check.py` 写了 `-> "NoReturn"` 却没 `from typing import NoReturn`。本地跑全量 pytest 不跑 ruff，两个 matrix job 的 "No undefined names (F821)" 步骤全红。**本地验证清单必须包含 CI 的那条 ruff 命令**：
   `ruff check . --select F821 --exclude node_modules,outputs,proxy,references --output-format concise`
   （不带这个 exclude 会看到 `references/ChartInsight/utils/pies.py` 一个无关的既有 F821）。

### 网络/推送铁律（本轮反复踩）

- 本机 `git config http.proxy = http://127.0.0.1:7890`；环境变量另有 WorkBuddy 代理 `127.0.0.1:4024`。
- 4024 对 github.com 返回 `CONNECT tunnel failed 502`；完全清代理直连则 `Could not connect to github.com:443`；7890 的 schannel 握手会间歇性失败但**重试通常能成功**。
- 可用命令：`git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 push origin main`。
- `gh`（api / release / run）走另一条通道，在 git push 全挂时仍可用。
