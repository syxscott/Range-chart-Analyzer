## 对抗复检（修复自身的审查，交付 `docs/ADVERSARY-2026-10-17.md`）

用户要求回查。**测试全绿对「修复是否正确」零信息量**，故对每处改动构造「修复前会过、修复后可能错」的输入实测。发现 3 个真问题，全已修。

**A1（P1，我亲手引入）** 同步 JS 端时把「返回原始值」写成 `String(v).trim()` 反查——**那不是投票键**（`rcaStrForMerge` 才是，它把积分浮点归一为 "1"、非有限值归一为 "NaN"）。后果：`[1.0,1]` 两端分歧、`[1,1.0]` Python 侧**顺序依赖**、`[NaN,NaN]` JS 得 `null`（而 `null` 正是"无共识"的写法，看起来像值被吞）。**1340 个差分用例全一致，0 diverged**——因为 `[1.0,1]` 本来就在 fixture 里，它当时通过恰恰因为两端都还返回投票键。修法：`rcaAggMode` 本身有 representative map，多余那层删掉即可。
- **教训**：`js/` 里「投票键 = X」与「值 = X」是两回事。改任一端前先找到该模块真正的键规范化函数（此项目是 `rcaStrForMerge`，Python 对应 `_str_for_merge`）。

**A2（P1）** `bed_parser` 的两条新规则照虚构标签写，误杀真实测井标注：`87 B1-4C`、`87 JED 8` 从 4/8 变 None。两个消费方（导出唯一阻断不变量 `range_base_le_range_top` + extractor 端点交换启发式）对该类图**整体停摆且不报错**。修：区间要求数字相邻（或同前缀 `A1-A5`）；外来词改**封闭清单** `_NON_POSITION_WORDS`，未收录词视为标识符。
- **教训**：**规则类修复必须用生产数据里出现过的字符串验**，不能只用自己造的样例。放射虫测井的 `87 B1-4C` / `CAASP-84-20/15` / `87 JED 8` 是现成的。
- **教训**：开放式规则（"不在白名单就算非法"）在识别「无关内容」时方向反了——白名单越补越漏。封闭清单（"只有已知的才算"）才是保守方向：漏检不报，误判才造假数据。

**A3（P2）** 差分 harness **结构性承载不了非有限值**（生成器拒绝，因 `JSON.parse` 不认裸 `NaN`），而 A1 破坏的正是这类值。补 `tests/test_aggregate_scalar_type_2026_10_17.py` 直接对两端探测（用 JS 源文本传参，`repr(nan)` 是 `nan` 而 JS 要 `NaN`），fixture 补 13 个可承载用例（1340→1353）。

**A4（P0，审查者报告→我实测确认）** 与 A1 同一处代码，改到第三轮才对。类型保留同时丢了 `_merge_scalar_field` 建池时的 `.strip()` → `"Ml"` 与 `" Ml "` 成两个平票候选、排序破平取回带空格版（`" Ml "`/`" 7 "`/`" -1 "`），Python 全给 trim 后值。**fixture 有 23 处带空白串，但没有一个让同一 merge 字段跨 run 同时有 padded+unpadded —— 触发路径存在、触发条件不存在**，所以 1340 个用例一路报 0 diverged。
- **修法（与 Python `votes` 列表逐行等价）**：池存 `(trimmedKey, original)` 对；键 = `rcaStrForMerge(v).trim()`；`if (sawText && sawNumber) return winning` **必须在代表值查找之前**（位置错 → `[" 7 ",7]` 两端分歧）。
- 我在这一处犯了**三次**「看起来等价」的错误：键函数用错（`String().trim()` 而非 `rcaStrForMerge().trim()`）、代表值取错（trim 后的值而非原值）、类型判断位置错。三次都只能靠实测对照表发现。
- **教训：跨语言复刻函数要逐行对照对方的控制流，不是逐句抄。** Python 那句 early-return 的顺序在代码里看不出重要性，换到 JS 就是实际答案不同。
- **教训：自己的修复需要第二双眼睛。** A4 的输入形状在我第一轮自查的集合里根本不存在。
