1. 按钮置灰**必须**写在门控里而非槽内手动 `setEnabled(False)` —— 因为 `_update_result_actions` 会被每个进度事件重跑，手动置灰下次就被恢复。
2. 给 worker 传 `tr.t` 而非 `self._t` —— `self.tr` 是共享可变状态（`retranslate()` 会中途换语言），worker 线程调会竞争。
3. **`closeEvent` 补 worker 是我清单里没有但必须加的**：openpyxl 无中断点，导出不可取消，用户中途关窗时 GC 回收**运行中**的 QThread 会触发 Qt6 `qFatal("Destroyed while thread is still running")` 直接崩进程。

**我把他的 4 条"静态推断"全部用 PyQt6 真实事件循环实测证实**：

- **信号 FIFO：`['done', 'finished']`** ✓ —— 所以 `_forget_xlsx_worker` 不会抢在 done 处理前清引用 ✓
探针固化：`tests/qt_export_gate_probe.py`。

**探针自己踩到一个 PyQt 陷阱（值得记）**：`w.done.connect(Page().on_done)` 用临时对象作接收者 → PyQt 只弱引用它 → 被 GC → **槽静默不执行**（表现为"handler fired: False"，看起来像业务 bug）。gui_fluent.py 安全（接收者是 `self`），但这个失效模式值得记住：**"槽从不执行"与"业务失败"在表象上无法区分，必须显式断言槽被调用**。
