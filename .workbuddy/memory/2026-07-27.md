## BugFix：Fluent GUI 启动崩溃（gui_fluent.py）
用户用 Anaconda `dev` 环境（`D:\Program Files\ananconda3\envs\dev\python.exe`，PySide6/Qt6）跑 `main.py` 报 `AttributeError: QWebEngineSettings has no attribute LocalContentCanAccessLocalResources`（`gui_fluent.py:331`，PhyloTreeWidget.__init__）。
- 根因：Qt6 把 WebEngine 属性移入 `QWebEngineSettings.WebAttribute` 枚举，且把 `LocalContentCanAccessLocalResources` **重命名**为 `LocalContentCanAccessFileUrls`；旧式 `QWebEngineSettings.LocalContentCanAccessLocalResources` 直访已不存在。
- 修复：`gui_fluent.py` 三处 `setAttribute` 统一走 `_WebAttr = getattr(QWebEngineSettings,"WebAttribute",QWebEngineSettings)`，本地资源属性按候选 `("LocalContentCanAccessFileUrls","LocalContentCanAccessLocalResources")` 回退（任一不存在时静默跳过）。
- 验证：用用户的 Anaconda dev python 实跑属性解析，确认无 AttributeError。
- 注：此 Bug 与之前的整改无关（整改未动过 gui_fluent.py），是运行 GUI 时暴露的预存在问题。

## BugFix：Fluent GUI 顶部/左侧黑框（真因=Mica）
GUI 能启动后，用户反馈顶部标题栏 + 左侧导航栏是纯黑，且其 Windows **未开深色模式**。
- 真因：`qfluentwidgets/window/fluent_window.py:33` 默认 `self.setMicaEffectEnabled(True)`——QFluentWidgets 的 `FluentWindow` 默认开启 Win11 Mica 材质效果（`setMicaEffect(self.winId(), isDarkTheme())`）。Mica 是 DWM 特性，在虚拟机/远程桌面/部分集显驱动/Win10 上静默失败，标题栏+导航栏垫底变纯黑。且 `fluent_window.py:57` `_normalBackgroundColor()` 在 Mica 开启时返回 `QColor(0,0,0,0)`（透明黑），所以 `setCustomBackgroundColor` 在 Mica 开着时被跳过——这正是上一版单改 setCustomBackgroundColor 无效的原因。
- 修复：`gui_fluent.py` `main()` 在 `win.show()` 前先 `win.setMicaEffectEnabled(False)`（关 Mica → 走 `setBackgroundColor(自定义色)`），再 `win.setCustomBackgroundColor(QColor(243,246,250), QColor(32,32,32))`（浅灰/深灰而非纯黑）。补 `from PySide6.QtGui import ... QColor`。
- 验证：offscreen 实例化确认 `setMicaEffectEnabled(False)` 后 `isMicaEffectEnabled()==False` 且无报错；`setMicaEffectEnabled` 在 `sys.platform!='win32' or build<22000` 时早返回（Win10 本就不开 Mica），故 Win10/Win11 均适用。
- 注：`setMicaEffectEnabled(False)` 在真机 Win11 才会执行 disable 分支（build>=22000），关闭材质后使用主题背景，黑框消除。若用户想保留 Mica 玻璃质感需确保其机器原生支持（VM/RDP 下不行）。
